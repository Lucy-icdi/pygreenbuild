# pygreenbuild 套件架構說明

`pygreenbuild` 面向 GreenBIM 應用，主要處理天氣資料擷取與 WRF 預報修正相關流程。套件核心規劃採典型 **ETL 管線**（Extract → Transform → Load），以四個層級串接資料從「取得」到「輸出」的完整路徑；另以 **metrics** 層承載成效／KPI 等領域計算邏輯，與 ETL 解耦。

## 資料流總覽

```
ingestion → parsers → transform → load
（擷取）    （解析）   （轉換）     （輸出）
                              ↘
                               metrics
                              （成效／KPI 計算）
```

| 層級 | ETL 對應 | 定位 | 主要用途 |
|------|----------|------|----------|
| **ingestion** | Extract | 資料來源層 | 從外部把原始資料抓進來；只負責取得，不負責清洗。 |
| **parsers** | Extract / Parse | 格式解析層 | 將各來源原始格式解析成統一可處理的結構。 |
| **transform** | Transform | 轉換／正規化層 | 欄位對應、格式偵測與正規化，產出標準表格。 |
| **load** | Load | 輸出層 | 將結果寫出至 CSV、資料庫等目的地。 |
| **metrics** | （非 ETL） | 成效計算層 | 依公式計算設備／系統成效與 KPI（如冰水主機）。 |

規劃上可由 `run_pipeline.py` 串起 **parser + transform + load** 的完整管線；成效計算可在標準資料產出後呼叫 **metrics**。

---

## 1. ingestion（資料來源層）

負責對接外部資料來源，將原始資料拉進系統。

規劃子模組：

- **weather / weather_crawler**：氣象爬蟲（由原 `weather_crawler` 升級）
  - CODIS 年／月／日報表
  - Cookie 管理
  - CWA 測站清單
  - GreenBIM / ICDI API（如 WRF 相關下載與匯出）
- **email**：郵件來源讀取
- **ems_db / factory**：廠區或 EMS 資料庫讀取

設計原則：此層只做「拿到資料」，不做欄位清洗或業務轉換。

---

## 2. parsers（格式解析層）

將各來源的原始內容解析成後續可處理的結構，是管線中的核心銜接點。

規劃模組：

- `weather_parser.py`：天氣相關原始資料解析
- `excel_parser.py`：Excel 檔案解析
- `factory_parser.py`：廠務／工廠來源解析

設計原則：來源格式差異在此消化，讓 `transform` 面對相對一致的資料形狀。

---

## 3. transform（轉換／正規化層）

對已解析資料做標準化，對齊統一欄位命名與資料品質規則。

規劃模組：

- `mappings.py`：欄位對應（例如 CWA 中文欄位 → 標準英文欄位）
- `detector.py`：依資料內容偵測適用的 mapping（日／時／月等）
- `normalize.py`：正規化與清洗（規劃建議）
- `json_to_dataframe.py`：JSON → DataFrame 轉換與清洗

設計原則：產出可供分析、特徵工程或匯出使用的標準表格。

---

## 4. load（輸出層）

將轉換完成的資料寫到最終目的地。

規劃模組：

- `to_csv.py`：輸出 CSV
- `to_database.py`：寫入資料庫

設計原則：與來源、解析、轉換解耦，同一份標準資料可對應多種輸出方式。

---

## 5. metrics（成效計算層）

承接已標準化的運轉資料，依領域公式計算成效與 KPI。不負責抓取、解析、欄位對應或寫檔。

現有模組：

| 模組 | Class | 用途 |
|------|-------|------|
| `chiller_usrt.py` | `ChillerUSRT` / `ChillerUSRTCalculator` | 冷房需求 USRT（含融冰、區域泵） |
| `chiller_performance.py` | `ChillerPerformance` / `ChillerPerformanceCalculator` | COP、耗電率 |

設計原則：公式與業務 KPI 獨立成層，供報表、分析或後續 `features`／模型呼叫。

### 5.1 `chiller_usrt`：冷房需求 USRT

**核心公式**（流量先轉 L/min、溫度先轉 ℃）：

```
熱量值 kW = Flow(L/min) × |入水溫 − 出水溫|(℃) × 4.186 / 60
USRT      = 熱量值 kW × 0.284   （kw_to_usrt=True，預設）
```

若 `kw_to_usrt=False`，回傳熱量值 kW（不乘 0.284）。

**常見流量換算**（原始單位 → L/min）：

| 單位 | 係數 |
|------|------|
| CMH (m³/h) | × 16.7 |
| CFM | × 28.3 |
| LPM | × 1（不換） |

```python
from pygreenbuild.metrics import ChillerUSRTCalculator

# --- 單台冰水主機 ---
usrt = ChillerUSRTCalculator.calculate_single_chiller_usrt(
    flow_rate=17.49,
    flow_unit="CMH",          # 原始流量為 CMH，內部 ×16.7 → LPM
    return_temp=13.28,
    return_temp_unit="C",
    supply_temp=8.86,
    supply_temp_unit="C",
    kw_to_usrt=True,          # True→USRT；False→熱量 kW
)

# 溫度也可分開用華氏 / 克氏
usrt_f = ChillerUSRTCalculator.calculate_single_chiller_usrt(
    flow_rate=2500, flow_unit="LPM",
    return_temp=54.5, return_temp_unit="F",
    supply_temp=44.6, supply_temp_unit="F",
)

# --- 多個區域泵加總 ---
total = ChillerUSRTCalculator.zone_pumps_total([
    {"flow": 10, "return_temp": 12, "supply_temp": 7, "flow_unit": "CMH"},
    {"flow": 8,  "return_temp": 12, "supply_temp": 7, "flow_unit": "CMH"},
])

# --- 融冰 ICE_RT（預設流量單位 CFM，負流量取絕對值）---
ice_rt = ChillerUSRTCalculator.ice_melt(
    -148.38, hex_return_temp=15.39, hex_supply_temp=9.93, flow_unit="CFM"
)

# --- DataFrame 批次：三欄 → 併回 USRT 欄 ---
import pandas as pd

df = pd.DataFrame({
    "flow": [17.49, 20.0],
    "return_temp": [13.28, 14.0],
    "supply_temp": [8.86, 9.0],
})

df = ChillerUSRTCalculator.calculate_usrts(
    df,
    flow_col="flow",
    return_temp_col="return_temp",
    supply_temp_col="supply_temp",
    flow_unit="CMH",
    result_col="USRT",
    kw_to_usrt=True,
)
```

主要方法：

| 方法 | 說明 |
|------|------|
| `calculate_single_chiller_usrt` | 單台冰水主機 USRT |
| `zone_pumps_total` | 多區域泵加總 USRT |
| `ice_melt` | 融冰 USRT |
| `calculate_usrts` | DataFrame 逐列計算，結果併回原表 |

### 5.2 `chiller_performance`：COP 與耗電率

**公式**（USRT 須先由 `chiller_usrt` 求出）：

```
製冷能力 (kW) = USRT / 0.284
COP           = 製冷能力 (kW) / 輸入功率 (kW)
耗電率        = 輸入功率 (kW) / 製冷能力 (USRT)
```

參考範例（2023/9/20 10:00）：USRT=1149、功率=410.6+233.35 → COP≈6.28、耗電率≈0.56。

```python
from pygreenbuild.metrics import (
    ChillerUSRTCalculator,
    ChillerPerformanceCalculator,
)

# --- 單筆 ---
cop = ChillerPerformanceCalculator.calculate_cop(usrt=1149, power_kw=643.95)
rate = ChillerPerformanceCalculator.calculate_power_rate(usrt=1149, power_kw=643.95)

# --- DataFrame：先算 USRT，再算 COP／耗電率 ---
df = ChillerUSRTCalculator.calculate_usrts(
    df,
    flow_col="flow",
    return_temp_col="return_temp",
    supply_temp_col="supply_temp",
    flow_unit="CMH",
    result_col="USRT",
)

df = ChillerPerformanceCalculator.calculate_performance(
    df,
    usrt_col="USRT",
    power_cols=["CH_02", "CH_04", "CH_B01"],  # 多欄功率會加總
    cop_col="COP",
    power_rate_col="耗電率",
)
# 結果多出：輸入功率_kW、COP、耗電率
```

主要方法：

| 方法 | 說明 |
|------|------|
| `calculate_cop` | 單筆 COP |
| `calculate_power_rate` | 單筆耗電率（kW/USRT） |
| `calculate_performance` | DataFrame 批次算 COP + 耗電率，併回原表 |

示範腳本：`tests/scripts/usrt_test.py`、`tests/scripts/performance_test.py`。

## 目錄對照（規劃）

```
src/pygreenbuild/
├─ ingestion/          # 資料來源層
│  ├─ weather_crawler/
│  ├─ email/
│  └─ ems_db/
├─ parsers/            # 格式解析層
├─ transform/          # 轉換／正規化層
├─ load/               # 輸出層
└─ metrics/            # 成效計算層
   ├─ chiller_usrt.py          # 冷房需求 USRT
   └─ chiller_performance.py   # COP、耗電率
```

> 註：後續還規劃了 `features`、`models`、`api`、`config`、`utils` 等模組，用於特徵工程、模型訓練／預測與服務化；本文件說明 ETL 四層與 metrics 成效計算層。
